# meteor-durable — the LLM harness for Meteor

**Site: https://10thfloor.github.io/meteor-durable/**

Eight imagined Meteor primitives, built for real as local Atmosphere packages
(`packages/`) — workflow, entity, keyring, lens, mcp, agent, memory, sandbox —
composed into an expense app where an AI agent does the triage, 3-of-5 humans
hold the keys, and every long-running thing survives a `kill -9`.

Born from a design conversation: *Meteor made realtime a default instead of a
feature; these make durability a default instead of a feature — and because the
journal is a collection, everything is observable from the client for free.*

## The primitives (`packages/`)

| Package | Primitive | One-liner |
|---|---|---|
| `durable:entity` | `Meteor.entity` | Keyed durable state with serialized methods; `Budget('engineering').reserve(50)`, reactive `watch()` |
| `durable:workflow` | `Meteor.workflow` | Journaled steps + compensation, typed signals, durable sleep, resume-on-boot, `Collection.trigger` (exactly-once) |
| `durable:lens` | `Meteor.lens` | Writable views: field renames, `readonly`, custom get/set with `{ userId, now }` context, `where` + `onEscape: 'forbid'` |
| `durable:keyring` | `Meteor.keyring` | Threshold-gated methods with real FROST-ed25519 (RFC 9591): **no dealer** — the key is co-generated by a Pedersen DKG (Feldman VSS + Schnorr PoK, round-2 shares E2E-encrypted); two-round signing on the custodians' devices aggregates to a standard ed25519 signature; `t-of-n` configurable via settings |
| `durable:mcp` | `MCP.server` | Methods as MCP tools (`MCP.expose`), lens views as resources, Bearer auth = Meteor login token |
| `durable:agent` | `Meteor.agent` | Durable AI agents — a workflow whose steps are LLM turns + tool calls; tools are importable callables whose type carries their gating (a keyring tool parks for human co-sign); transcript is the journal |

Each package README lists its honest deviations from the fantasy sketch.
The app itself is `server/ledger.js` (~120 lines) + a Blaze dashboard.

## Run it

```bash
meteor
```

Open http://localhost:3000 — sign in as `frank` (any seeded user, password
`password`), submit an expense, watch the pipeline. Approvers: `alice`,
`bob`, `carol`, `dave`, `eve`.

The agent's front door (token printed at boot):

```bash
# what the agent sees — the lens view, three fields, nothing else
curl -s -X POST http://localhost:3000/mcp/ledger \
  -H 'Authorization: Bearer redacted-demo-token' -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"resources/read","params":{"uri":"ledger://expenses/pending"}}'

# record a verdict (starts the money moving — pending 3-of-5 human signatures)
curl -s -X POST http://localhost:3000/mcp/ledger \
  -H 'Authorization: Bearer redacted-demo-token' -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"triage","arguments":{"expenseId":"<id>","verdict":"approve"}}}'
```

## The durability demo

Kill the server while a workflow is parked mid-`await pay()` with a partial
quorum. On restart the boot log prints:

```
[durable:workflow] resuming fulfill:<expenseId> (was: running @ reserve budget)
```

The journal replays (completed steps skipped, compensations re-registered),
the run re-parks inside the same `await`, re-attaches to the same pending op
by args-hash, and the remaining signatures complete it — one payment, not two.
